# RealSaS — Architecture Authority Ledger V1

**Date:** 2026-09-07  
**Scope:** cross-chat / cross-agent architecture reconstruction  
**Continuation authority:** `CURRENT_STATE.md` on `main`

This ledger does **not** independently authorize promotion. It answers one narrow question: **for each important mechanism, where is it implemented, what has actually been tested, and is it current product architecture or only research lineage?**

A mechanism is not considered remembered merely because a report or source file exists. It is considered reconstructed only when this ledger identifies its implementation/evidence/canonical status.

## Status vocabulary

- `BINDING` — current architectural responsibility/invariant on `main`.
- `MAINLINE_ON_HOLD` — current source exists but architecture refreeze/promotion is blocked by `CURRENT_STATE.md`.
- `IMPLEMENTED_RESEARCH` — executable challenger/mechanism exists but is not product authority.
- `TESTED_COMPONENT` — the named mechanism has controlled or diagnostic evidence, but this does not imply full-formulation validation.
- `ACTIVE_EXPERIMENT` — currently under a preregistered unresolved experiment.
- `OPEN_REQUIREMENT` — required responsibility with no closed promoted solution yet.
- `FORBIDDEN` — prohibited product behavior.

## Critical anti-conflation rules

1. **Source exists != mechanism tested.**
2. **Mechanism tested != full formulation tested.**
3. **Research challenger exists != canonical Geppetto contains it.**
4. **Binding architectural requirement != promoted executable consumer.**
5. **FIT1 witness success != generalization evidence.**
6. **A result on AR-01 cannot be labeled a RigAnything-formulation verdict.**
7. Before saying "RealSaS lacks mechanism X", search this ledger for X and inspect the listed research implementation as well as mainline.

## Required update transaction

Any experiment that changes an architecture belief is incomplete until all of the following are reconciled in one promotion/decision transaction:

1. exact implementation path + commit;
2. exact experiment/prereg/result pointer;
3. this ledger row status;
4. `canonical/EXPERIMENT_AUTHORITY_LEDGER_V1.md`;
5. `CURRENT_STATE.md` when continuation/stop-go changes;
6. explicit supersession/revocation statement for the previous interpretation.

Do not create a second competing mechanism ledger. Extend this file or explicitly supersede it from `CURRENT_STATE.md`.
