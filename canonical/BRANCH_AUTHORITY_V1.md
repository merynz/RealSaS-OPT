## Promotion rule

If an active or historical side branch produces content that should become canonical implementation on `main`, promotion requires an explicit `main` transaction recording:

1. source branch and exact source commit;
2. exact evidence/result/implementation being promoted;
3. compatibility and reconciliation with current `main`;
4. updated `CURRENT_STATE.md` and machine authority/context maps;
5. explicit distinction between implementation promotion, scientific PASS and PRODUCT_PASS.

No implicit branch switch or silent replacement is allowed.
