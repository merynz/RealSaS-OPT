# RealSaS-OPT Research Execution Protocol V2

**Status:** binding for new canonical research runs after 2026-08-20.

## Goal

Canonical research must be reproducible without recovering transient notebook state, guessing helper semantics, or post-hoc reconstructing executable source. A result is canonical only when the exact executable source, exact immutable inputs, preregistration, machine result, and decision are linked by hashes and persistent locators.

## Authority model

- **GitHub:** sole code/version/provenance authority.
- **Google Drive:** heavy immutable data/checkpoint/cache depot and source-bundle mirror.
- **ChatGPT Library:** source/manifest/result audit mirror.
- **Local runtime/notebook:** disposable execution cache; never provenance authority.

No persistent store may silently replace another. Conflicts are reported, never reconciled by choosing the convenient copy.

## Canonical experiment state machine

A run advances only in this order:

1. `QUESTION_FROZEN` — scientific question, claim boundary, population and forbidden operations written.
2. `SOURCE_FINALIZED` — executable modules contain no placeholders or notebook-only logic.
3. `STATIC_TESTS_PASS` — unit/synthetic tests and authority-boundary tests pass.
4. `SOURCE_BUNDLE_FROZEN` — immutable bundle built; SHA-256 computed.
5. `SOURCE_THREE_STORE_PASS` — exact source bundle persisted and verified in GitHub, Drive and Library.
6. `INPUT_MANIFEST_FROZEN` — every checkpoint, raster/corpus shard, parent artifact and evaluator source is identified by SHA-256 and locator. Derived populations are explicit ID manifests, not prose counts.
7. `PREREG_FROZEN` — thresholds, metrics, decision tree and invalidation guards fixed while evaluation truth is still unopened.
8. `OBSERVABLE_PREDICTION_FROZEN` — truth-free inference is executed and its state/result hash is sealed.
9. `TRUTH_OPEN` — evaluator-only truth may now be accessed. It may label or score predictions but may not alter inference state.
10. `RESULT_FROZEN` — machine result + execution log + hashes written atomically.
11. `REPORT_DECISION_FROZEN` — human report and decision are derived from the machine result without changing preregistered thresholds.
12. `THREE_STORE_RESULT_PASS` — source manifest, prereg, result and report mirrored/verified.
13. `STATE_PROMOTION` — only then may `CURRENT_STATE`/`STATUS` advance.

Any failure stops the state machine. No downstream state may repair an earlier missing gate retroactively.

## Experiment directory contract

Each canonical experiment owns one append-only directory:

```text
research/<area>/<experiment_id>/
  README.md
  SOURCE_MANIFEST.json
  INPUT_MANIFEST.json
  PREREG.md
  src/
  tests/
  run/
    OBSERVABLE_STATE.json
    RESULT.json
    EXECUTION_LOG.txt
  REPORT.md
  DECISION.json
```

Canonical files are never overwritten by a later experiment. A code change creates a new experiment/source version.

## Truth firewall

Inference code and evaluator code are separate modules/process phases.

**Observable phase may read only:** rasters, calibrated camera contract, frozen checkpoint, observation-derived candidates/evidence, and explicitly frozen parent artifacts.

**Evaluator phase may additionally read:** exact sidecars/teacher targets required for scoring or counterfactual selection.

The evaluator may select an evaluator-only counterfactual candidate, but no teacher field may enter `P_B`, `N_B`, `V_B`, descriptors, solver costs, or any other forward-mechanics input unless the prereg explicitly defines a truth-open oracle experiment.

For geometry counterfactuals, candidate `N_B` and `V_B` must be regenerated by the same raster-observable inference front door used in production, not copied from dense teacher surface samples.

## Derived populations

A number such as `n=492` is not an authority artifact. The exact member IDs must be frozen:

```json
{
  "population_id": "...",
  "producer_source_sha256": "...",
  "input_manifest_sha256": "...",
  "members": [{"family": 9908, "carrier": 17}, ...]
}
```

Downstream experiments consume this manifest. They do not silently recompute the population with copied helper code.

## Parent artifact policy

A persisted cache may be consumed as an immutable input if its SHA-256 is frozen, but its provenance class must be explicit:

- `REPRODUCIBLE_PARENT`: producing executable source and inputs are available and verified.
- `FROZEN_DATA_PARENT`: exact cache bytes are available but producing source is unavailable; downstream claims may use the cache as data but may not claim end-to-end reproducibility from raw observations.
- `UNRECOVERED_PARENT`: neither exact source nor a verified exact parent artifact is available; it cannot be a canonical dependency.

Prefer a clean new experiment from reproducible parents over source reconstruction. Recovery is exceptional forensic work, not the default continuation mechanism.

## No-overwrite rule

Canonical source bundles, manifests, preregs, results and reports are append-only. Mutable scratch/caches live outside canonical directories and include `SCRATCH` in their path. Canonical execution refuses to write over an existing result.

## Automatic preflight

Every canonical run must execute `tools/research_preflight.py` against `SOURCE_MANIFEST.json` and `INPUT_MANIFEST.json`. The run aborts on:

- missing persistent locator;
- missing SHA-256;
- local hash mismatch;
- unverified source test state;
- placeholder locator/value;
- missing evaluator/checkpoint identity;
- result path already existing.

## Notebook policy

Notebooks may orchestrate and visualize only. They may not contain the only implementation of candidate construction, solver logic, evaluator semantics, thresholds, or data mapping.

## Recovery policy

If an old canonical result lacks exact source bytes, retain it as historical evidence with the provenance defect stated. Do not spend normal research cycles reconstructing it unless the old result is uniquely necessary. Prefer a new versioned experiment using current reproducible inference.

A reconstruction, if unavoidable, is a separate experiment and cannot inherit canonical authority merely by matching aggregate metrics.

## Promotion rule

A PASS/FAIL scientific result and an infrastructure/provenance PASS are separate. Scientific interpretation is authorized only when provenance gates pass. A scientifically interesting run with failed provenance remains `NONCANONICAL_DIAGNOSTIC`.
