# Visual relationship closure — 2026-10-10

## Acceptance requested by the user

Every relationship requires an identifiable producer, a sealed artifact,
an actual consumer, and an independent output measurement over the required
domain. These are separate obligations. A connected DAG does not prove useful
data; useful data does not prove that playback consumed it. A visible defect
that violates the declared contract invalidates full acceptance even if every
existing narrow check is green. A missing test, incorrect consumer or insufficient
producer must be attributed to its own boundary before another intervention.

The frozen Knight M/G/W is the current witness boundary only. Future models,
heads, datasets and evaluations remain replaceable through released DAG changes.

## Boundary evidence added to the real pipeline

Stage42 verifies the completion sidecar's bytes, shapes and donor/provenance
pairings, and records actual canonical sample counts separately from zero visual
transport samples. This is validation consumption, never a claim of colour
transport or hidden-support qualification.

The immutable projection binds `SourceVisualBoundaryEvidence.v1` to the exact
appearance asset, qualification and Stage37 presentation. Stage43 writes the
same evidence into RSS. Stage45 checks its hash, the RSS payload and those three
bindings before measurement, and records `full_visual_acceptance_passed=false`.
Stage46's existing hidden-material/contact/order gates remain closed. Tests use
the real Stage20–46 adapters and native player; corruption, a changed donor and
an optimistic resealed PASS flag are rejected. These tests establish engineering
enforcement, not Knight visual closure or unseen/model evidence.

The main host workflow now performs the read-only sealed-input preflight first.
An incomplete boundary produces an explicit failed inspection and preserves the
evidence, instead of spending another full render on a path already known to lack
required contracts. Source SHA directories keep old witnesses intact. This run
does not create an Attempt, ProductRevision or new scientific qualification.

## Diagnostic faults also made observable

Raster rejection now separates depth-tie and fragment-overflow counts, with
bounded pixel/face/depth examples. Thresholds and rendering mathematics are
unchanged. The diagnostic runner also records geometry failures; a completed GIF
with flipped triangles or an edge ratio above the existing canonical threshold
4.0 cannot be reported as a successful structural render. Full visual acceptance
remains separately false.
