## Why V17 exists

The pre-V17 `SOURCE_LOCUS_GEOMETRIC_RAYS_V1` pilot measures geometric ray stacks on **rest geometry**. But V13b–V16 show actual original source geometry changing under authored animation and concurrent controls. Reusing a rest ray address as the front/behind or editable contribution address of a different posed mesh would be scientifically wrong.

V17 does **not** rerun original Blender or recolor/segment source artwork. It opens the already SHA-courted *real* V14 source single-control images and V16 joint source world vertices and appearance, with the **original calibrated V14 camera and exact immutable rest/source face triangle indices**. At each of 3 authored poses × 4 actual source views × 4 actual signed A+B interventions, it independently samples up to 12 pixel rays from **posed triangle centroids, without using RGBA outcomes or any artist semantic target to select locations**.

The source geometry ray oracle returns every hit, the original source face ordinal, world-space barycentric address, ordered geometric depth and typed tie/completeness state. The image join measures the *same pixel in the same signed pose/view* from V14 original A, original B and V16 actual A+B/source baseline under premultiplied RGB and explicit alpha, detecting causal response, independent A/B additive-prediction violation and hidden-effect uncertainty. Original Blender bottom-up pixels are mapped to top-down product camera ray pixels via an explicit `buffer_y = 191 - geometric_y` convention, **not tuned to source response**.

This is geometry + image observation; **frontmost geometric hit does not prove actual alpha-blended visible material, a graphics drawable, ordered artist paint or a causal owner**. Transparent graphics and compositing remain unknown; EMPTY/TIED/INCOMPLETE geometry rays are typed UNKNOWN, not art absence.
