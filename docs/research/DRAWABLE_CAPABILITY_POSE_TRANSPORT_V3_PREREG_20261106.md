## Hypothesis and precise representation classes

Question: the same original texture-address editing operations are required to persist across *two different original source-authored poses*. Does a **pose-frozen image-space delta** (four source-rest camera planes; exactly one delta per camera/sample/edit) suffice, or must the representation have some form of pose-dependent edit transport?

Two candidate representation classes:
- \`R_fixed\`: **pose-frozen screen-space premultiplied RGBA delta**. It stores the FULL source edit difference \`Delta_i(view,sample)=single_i(pose0)-base(pose0)\` for every camera/edit/sample. At pose1 it can only output \`base(pose1)+Delta_i(view,sample)\`. This is an intentionally restricted class; **no per-pose warp, per-surface address lookup, dynamic image mask, dynamic geometry or redraw**. Evaluate every original sample pixel at .025 inherited max premultiplied RGBA channel error against independently rendered \`single_i(pose1)\`. Source heldout pose1 edit targets may never be used to choose the frozen delta.
- \`R_source_UV_native\`: the *original native source* mesh/material with source-top-left UV atlas edit bound to unchanged texel addresses, rerendered separately for both native poses. This is a **constructive physical source witness** of valid pose-dependent address handling, **NOT** a finished proposed real-time BUSTED compiler representation, GPU cost measurement or an inference proof. Equally capable alternate puppet representations with UV masks + deformation are not excluded.

Nonvacuity: all three edits must change >=32 source sample-pixel incidences across the 4 cameras in **both** native pose states; all atlas edit byte supports and original alpha preserved and explicit identical source PNG bytes across poses. Actual original source geometry between poses must move. Source RGB edit alpha drift must remain zero. No source pixel masking outside the original source-defined alpha/UV policies; do not discard troublesome pixels. Report per-pose/per-camera edit effect counts, frozen image-space delta errors, first failure pixel and actual difference, movement, and whether the effect support is lost and reappears with pose. A frozen screen-delta class FAIL is a representation-specific loss, **not** evidence that 3 drawables must be separated: richer one-drawable + surface-addressed controls could pass.
