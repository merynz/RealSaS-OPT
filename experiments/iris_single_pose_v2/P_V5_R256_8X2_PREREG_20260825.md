## Full 16-cell objective and A100 execution
Every optimizer step represents the **full 16-cell objective**.

Fixed execution decomposition:
- microbatch = 8 asset-style cells = 64 views;
- accumulation steps = 2;
- both microbatches are processed before every optimizer update;
- each microbatch loss is scaled by `1/2` before backward.

The model uses GroupNorm and zero-dropout transformer blocks, so this decomposition has no batch-statistics dependence. Preflight must additionally verify gradient-accumulation equivalence on a reduced deterministic synthetic case.

Each asset-style cell therefore participates in all `2560` scientific optimizer steps, matching the prior two-style exposure budget rather than diluting it by round-robin sampling.

Runtime: high-memory CUDA GPU; target execution is A100. Production preflight requires at least 35 GiB reported device memory and a successful R256 microbatch-8 forward/backward.

## PASS rule
At one preregistered checkpoint, **all 16 cells separately** require `P_p95 <= 0.005`.

Aggregate P95 cannot pass the gate and cannot hide any failing cell. Checkpoint selection minimizes:
1. worst-cell P95;
2. aggregate P95;
3. total optimizer steps.

PASS -> preregister unseen-family generalization only.  
FAIL -> remain on 8×2 and localize failure pattern (asset interference, optimizer tail, extractability/coherence, or capacity) before any architecture change. PatchMatch-style geometry-in-the-loop becomes eligible only if controlled residual evidence localizes the blocker accordingly.
