# RealSaS IRIS/TESSA — Architecture Premise Search Map V1

**Date:** 2026-10-25  
**Status:** `ACTIVE_RESEARCH_MAP__NO_ARCHITECTURE_FROZEN`  
**Purpose:** turn every important V3 design assumption into an explicit falsifiable variable before causal Truth/FIT8 conclusions are drawn.

## Core rule

The current V3 architecture is a **candidate apparatus**, not the hypothesis itself.

The scientific hypothesis is broader:

> useful geometry, mechanics and graphics evidence can be inferred from observations and coupled strongly enough that role-free causal evidence improves structuralization and can be compiled into an editable canonical graphics/mechanics program.

A single undifferentiated shared Z, triplanes, FlexiCubes, a particular query MLP, current head parameterizations, or the current TESSA autoregressive decoder are implementation hypotheses inside that larger claim.

No premise is protected from comparison merely because papers use it or because it already exists in code.

---

## Search discipline — avoid combinatorial explosion

A naive Cartesian sweep is forbidden. Search proceeds in levels.

### L0 — deterministic legality / information proofs
Cheap source, algebra and identifiability courts. Eliminate impossible or internally inconsistent treatments.

### L1 — synthetic mechanism courts
Construct the smallest task that requires exactly the mechanism under test. Include a random-label / impossible-task firewall where applicable.

### L2 — matched micro-learning courts
Compare surviving alternatives with matched information, parameter, token, carrier and optimizer budgets. Run multiple seeds.

### L3 — interaction courts
A local winner is not assumed to remain a winner jointly. Test interactions among selected treatments using pairwise or fractional-factorial designs before assembling a new architecture.

High-priority interactions include:
- carrier × query;
- scene sharing × objective family;
- scene sharing × fusion placement;
- extraction × witness sampling;
- extraction × topology decoder supervision;
- relation algebra × truth parameterization;
- presentation evidence × TESSA fusion/binding;
- tokenization × attention/window semantics.

### L4 — authored causal truth courts
Use qualified TeacherScene/Truth Foundry response truth. This is the first level that may support a scientific architecture selection for RealSaS.

### L5 — joint tiny system
Train/execute a bounded end-to-end IRIS→evidence→TESSA→Compiler-style research court to expose interactions that isolated probes miss.

### L6 — FIT8 / LOFO / unseen
Genericity and product-level evidence only after apparatus closure.

# Premise families

## P0 — observation sufficiency

Questions:
- RGB only vs RGB+alpha/support residual;
- frozen DINO final tokens vs early+final aligned tokens;
- DINO family / foundation alternatives only if current evidence justifies reopening;
- patch lattice resolution;
- raw/local residual branch;
- exact camera basis injection vs learned camera embedding;
- deterministic backprojection/ray features;
- number and placement of views;
- strict normalized A-pose vs later normalization stage.

Known: alpha discard is invalid; dual-level early+final is selected at tiny scale; exact backprojection treatment remains open.

## P1 — multi-view reconciliation

Candidate treatments:
- query-mediated current fusion;
- source self-attention before scene queries;
- epipolar/ray-aware deterministic routing;
- pairwise view matching then global fusion;
- hierarchical local-to-global view fusion.

Current tiny court supports query-mediated baseline but does not close harder geometry-aware reconciliation.

## P2 — scene carrier

Candidate carrier families:
- single-resolution triplane;
- multiresolution triplane;
- triplane + sparse residual 3-D grid;
- dense 3-D grid control;
- sparse voxel/octree/hash-grid carrier;
- point/anchor carrier + continuous query;
- hybrid plane/line factorization;
- learned local chart/surface carrier after geometry becomes available.

Compare under explicit memory/compute budgets and surface-relevant frequency ladders.

## P3 — local query operator Q(Z,x)

Candidate treatments:
- current concatenated plane samples → residual MLP;
- explicit xyz appended;
- Fourier/positional encoding of x;
- local multiscale samples;
- local neighborhood attention;
- SIREN/Fourier-style high-frequency query;
- family adapter after shared Q;
- family-specific Q over common Z;
- uncertainty/validity readout separated from evidence value.

Measure carrier capacity separately from query capacity.

## P4 — degree/location of scene sharing

Candidate treatments are preregistered in `SHARED_SCENE_PREMISE_PREREG_V1.md`:
- independent GM/GP scene states;
- late fusion;
- shared trunk + private subspaces;
- fully shared Z;
- shared Z + family adapters.

Primary concern: positive cross-modal transfer versus destructive negative transfer.

## P5 — field semantics

Do not assume one scalar field is optimal.

Candidate geometry field/objective families:
- SDF-like signed field;
- occupancy/logit field;
- unsigned distance + inside/outside auxiliary;
- density-like field;
- multi-field surface/boundary representation;
- direct local surface probability + normal/offset;
- hybrid coarse sign + local residual.

Required tests: topology observability, calibration, thin support, nested/close surfaces, gradient quality for extraction.

## P6 — extraction

Extraction is a search family, not one resolution knob.

Candidate dimensions:
- base resolution 24/32/48/64/...;
- fixed vs adaptive/coarse-to-fine grid;
- current pinned FlexiCubes vs justified alternative differentiable extractors;
- beta/alpha/gamma parameter range and regularization;
- field-only zero crossing vs learned extraction offsets;
- training extraction resolution vs inference extraction resolution;
- topology loss before/after extraction;
- component/noise cleanup location;
- manifoldness court;
- thin-support survival;
- close-surface separation;
- phase sensitivity;
- gradient stability near topology changes;
- extraction precision FP32 vs mixed precision boundary;
- deterministic reproducibility;
- surface witness generation after extraction.

Current observability court proves that resolution affects topology visibility before FlexiCubes deformation can help. It does not select an extractor or resolution.

## P7 — surface witness representation and sampling

Candidate treatments:
- current vertex-index sampling (already invalid as default);
- area-weighted deterministic sampling;
- farthest-point/geodesic coverage;
- curvature/boundary stratified sampling;
- component-qualified sampling;
- adaptive quota by visible/projected support;
- learned witness proposal with deterministic coverage floor;
- continuous query without discrete witness bottleneck for some heads.

Evaluate permutation invariance and rare thin/low-area support coverage.

## P8 — mechanics evidence parameterization

Questions:
- principal stretch major/minor + 2theta versus invariant tensor representation;
- tangent validity near isotropy;
- curvature/bend scalar versus directional tensor;
- rigidity probability versus continuous compliance;
- contact persistence scalar versus trajectory/event response;
- local versus pair/trajectory mechanics evidence.

Truth geometry must choose the objective, not checkpoint convenience.

## P9 — appearance/source evidence

Questions:
- view-conditioned RGBA directly from Q;
- source-space canonical appearance support plus view residual;
- explicit alpha/support channel;
- material/texture teacher information used only for truth qualification;
- high-frequency texture residual path;
- uncertainty/coverage and source ownership without semantic IDs.

## P10 — pair/relation algebra

Every learned quantity receives an algebra class before architecture selection:
- symmetric similarity/coherence;
- directed causal dependency;
- complementary order with tie/abstention;
- symmetric boundary/separation evidence;
- ray-global compositing quantity.

Candidate parameterizations should enforce algebra by construction where possible, then compare against unconstrained heads under matched capacity.

## P11 — ray/compositing representation

Candidate truth/model forms:
- first-hit binary visibility (known insufficient as final truth);
- incoming transmittance;
- per-hit alpha contribution;
- counterfactual contribution under removal;
- complete ordered stack transformer;
- deterministic compositor over predicted per-hit quantities;
- hybrid learned stack evidence + deterministic compositor.

Include transparent/partial-alpha/adversarial same-depth/tie cases.

## P12 — causal truth response geometry

Do not prematurely collapse response truth to one binary identity.

Candidate retained quantities:
- source-space appearance response vectors;
- rigid response transforms;
- deformation trajectories;
- pair distances/kernels;
- directed intervention influence;
- separation witnesses;
- ray/compositing responses;
- boundary-cause evidence;
- validity/abstention/provenance.

Model-facing labels are derived views of richer truth and may evolve without rebuilding authority truth.

## P13 — loss/objective family

Candidate by truth geometry:

- SmoothL1 / Huber continuous regression;
- cosine/directional objectives;
- ranking/triplet/contrastive objectives;
- trajectory correlation / spectral objectives;

No global 'one BCE for all relations' default.

## P14 — multi-objective optimization

Measure first:
- family gradient norms;
- pairwise gradient cosines;
- per-family single-task oracle gap;
- negative transfer under joint training.

Candidate treatments only after conflict is observed:
- fixed preregistered weights;
- uncertainty/adaptive weights;
- PCGrad-like surgery;
- gradient normalization;
- alternating family batches;
- partially private subspaces.

## P15 — presentation evidence schema

Selection must be relation-addressability and topology-performance based, not architectural elegance.

## P18 — TESSA decoder memory / attention

Candidate treatments:
- current local causal window;
- exact sliding window;
- recurrent/compressed long memory;
- component-level summary tokens;

- hierarchical/coarse-to-fine decode.

First measure real dependency span; do not increase window merely because maximum sequence length is large.

## P19 — TESSA objective

Current objective: token CE + coordinate metric + structural special-token loss.

Open alternatives:
- topology-aware decoded auxiliary court/loss if differentiable and authority-safe;
- component closure loss;
- geometric quality objectives;
- presentation-consistency objective;
- relation-preservation objective;
- teacher-forcing schedule / exposure-bias treatments.

All must preserve independent free-running court.

## P20 — Compiler-facing evidence boundary

The Compiler remains canonical authority, but evidence contract is searchable:
- which quantities are model evidence;
- which are deterministic derived evidence;
- which are Compiler-only decisions;
- how abstention propagates;
- when pre-M evidence binds to canonical mesh addresses;
- how mechanics and graphics courts combine.

No learned hidden ownership/identity is introduced merely to simplify Compiler code.

# Selection rule

There is no single local scalar objective for architecture search.

A treatment may advance only if it is on the Pareto frontier across:
- required truth-family accuracy/calibration;
- worst-family behavior;
- topology/structural downstream effect;
- Compiler agreement/coverage when available;
- parameter/token/memory/compute cost;
- seed stability;
- morphology stability;
- abstention correctness;
- editability/authority constraints.

A locally superior component can still be rejected after an interaction court.

# Final assembly rule

The eventual IRIS/TESSA VNext architecture is assembled only from treatments that survive both:
1. their isolated mechanism courts; and
2. at least one relevant joint interaction court.

The final joint result must then be re-tested from scratch. Component PASS records are necessary evidence, never sufficient evidence for whole-system success.
