# RealSaS — TESSA V3 Independent-Compression Addressability Probe Prereg V2

**Date:** 2026-10-25  
**Status:** `SEALED_BEFORE_V2_OUTPUTS`  
**Execution class:** tiny synthetic CPU learned probe; no product/ModelRelease authority.

## Why V2 exists

V1 is retained unchanged as evidence. Its preregistered firewall failed: the SHUFFLED_ENDPOINT arm achieved roughly the same ~0.59–0.60 accuracy as treatment. This is now explained analytically rather than treated as a model result.

In V1, the control endpoint was constrained to be different from the true target endpoint. Given the full set of 16 random payload bits and the known wrong endpoint, the hidden target is uniformly one of the other 15 loci. The Bayes-optimal classifier can therefore predict the majority payload among those 15 loci, with expected accuracy approximately `0.604736328125`. The observed control accuracy is consistent with this unintended information channel.

Therefore V1 yields **no architecture verdict**. V2 changes only the synthetic firewall/task reader needed to remove this confound and to isolate the intended mechanism.

## Question

Can the current TESSA V3 independent typed-memory compression preserve enough surface/presentation address information to retrieve the payload associated with an explicitly referenced surface locus?

## Synthetic sample

Same base data model as V1:

- 16 surface loci on a fixed 4x4 normalized coordinate lattice;
- independent fair payload bits `p_i in {-1,+1}`;
- random surface-token permutation every batch;
- uniformly random target locus `j`;
- true presentation token contains coordinate `(x_j,y_j)` and a constant type marker;
- treatment target is `p_j`.

Surface source token: `[x, y, payload]`.
Presentation source token: `[x_target, y_target, 1]`.
Scene source: four zero/nuisance tokens.

## V2 reader — two-hop typed lookup

V1 used one static learned query over the concatenated memory. That confounded endpoint join with whether a one-hop static query could itself compare presentation and surface addresses.

V2 uses an explicit two-hop reader after the **same current TESSA independent compression**:

1. one learned query attends only to compressed presentation memory;
2. the resulting presentation-conditioned query attends only to compressed surface memory;
3. residual + LayerNorm + MLP `64 -> 64 -> 1` predicts payload sign.

The reader sees stream boundaries by construction. It never sees raw source tokens in the treatment arm.

This tests whether independent compression preserves sufficient endpoint/payload information; it does not test the full TESSA decoder.

## Arms

### A — COMPRESSED_TRUE_ENDPOINT

Current TESSA tri-stream memory. True presentation endpoint. Target=`p_j`.

### B — COMPRESSED_RANDOM_LABEL_FIREWALL

**Inputs are byte-for-byte generated by the same TRUE_ENDPOINT procedure as A**, including the true endpoint. The training/evaluation target is instead an independently generated fair Bernoulli bit that is never inserted into any input tensor.

Because batches are freshly generated, this target has zero input information in expectation. This is the leakage/firewall control, not a treatment comparison.

### C — RAW_TWO_HOP_POSITIVE_CONTROL

No TESSA compression. Surface and presentation source tokens are separately projected to 64 dimensions with learned linear+LayerNorm+GELU maps and typed embeddings. The **same two-hop reader structure** then reads presentation followed by surface.

This arm is a mechanism positive control only. It asks whether the synthetic task and two-hop reader can learn exact coordinate-based retrieval when address/payload information is directly accessible. It is not capacity-matched to TESSA compression and cannot establish that raw input is a better product architecture.

## Preregistered interpretation

### Firewall validity

`COMPRESSED_RANDOM_LABEL_FIREWALL` must lie in `[0.45,0.55]` accuracy for every seed.

Otherwise: `V2_SYNTHETIC_FIREWALL_INVALID`; no mechanism conclusion.

### Positive-control validity

`RAW_TWO_HOP_POSITIVE_CONTROL` must achieve:

- every seed >= 0.90;
- mean >= 0.95.

Otherwise: `V2_READER_OR_TASK_NOT_ESTABLISHED`; compressed-memory conclusion withheld.

### Current compression mechanism accessibility

Only if firewall and positive control both pass, label `MECHANISM_ACCESSIBLE_TINY_V2` if:

- every compressed true-endpoint seed >= 0.90;
- mean compressed true-endpoint accuracy >= 0.95.

If firewall and positive control pass but compressed treatment does not:

`CURRENT_INDEPENDENT_COMPRESSION_ADDRESSABILITY_NOT_ESTABLISHED_TINY_V2`.

That result authorizes a separately preregistered compression/fusion treatment study. It does **not** prove reference TESSA fails or that early fusion is necessarily superior.
